# docs: document new CLI surface for 1.3.0

## Summary

Document the user-visible changes from the prior feature work in `README.md`: per-app `redirect_uri` flags and
subcommand, `auth oauth2 [USERNAME]` positional, `-u USERNAME` shortcut fallback, `--output json` for `auth status` and
`auth apps list`, and the X platform Pay-per-use Production enrollment workaround.

Version bumps and `CHANGELOG.md` regeneration happen on the `release/vX.Y.Z` branch per `RELEASES.md`, not on internal
dev PRs.

---

## Problem Frame

`README.md` does not yet document the user-visible CLI surface introduced by the prior feature PRs:

- `auth apps add/update --redirect-uri` flag and the `auth apps redirect-uri get/set` subcommand.
- Optional `[USERNAME]` positional on `xr auth oauth2` that bypasses `/2/users/me`.
- Shortcut `-u USERNAME` fallback that uses `/2/users/by/username/<u>`.
- Structured JSON output from `auth status` and `auth apps list` under `--output json`.
- The credential-less-default-app warning that prints when the user does not pass `--app` and the default app has no
  `client_id`.
- The X platform Pay-per-use Production enrollment workaround for the `client-forbidden`/`client-not-enrolled` symptom
  upstream documents in two places in its README.

## Requirements

### README

- R1. `README.md`'s `## Authentication` → `### Multi-App Management` section documents `auth apps update`, `auth apps
  redirect-uri get`, `auth apps redirect-uri set`, and the `--redirect-uri` flag on `add`/`update`.
- R2. `README.md`'s `## Authentication` → `### OAuth2 (Recommended)` section documents the optional `[USERNAME]`
  positional on `xr auth oauth2` and explains why a user might supply it (skip the `/2/users/me` lookup when X is
  flaky).
- R3. `README.md`'s `## Commands` adds a short note explaining that shortcut commands honor `-u USERNAME` and use
  `/2/users/by/username/<u>` instead of `/2/users/me` when set.
- R4. `README.md`'s `## Agent-Native Features` → `### Machine-Readable Output` documents that `auth status` and `auth
  apps list` honor `--output json` and emit a structured array per app.
- R5. `README.md` gains a new top-level `## Troubleshooting` section that includes the X Platform Enrollment workaround.
  The wording mirrors upstream's README (the dedicated `### X Platform Enrollment Troubleshooting` section) so users
  migrating from `xurl` (Go) to `xr` recognize the recipe.
- R6. `README.md` mentions the credential-less-default-app warning in the multi-app section so users know what the
  warning means before they encounter it.

### Verification

- R7. `markdownlint-cli2` passes (project lint runs on hook); `cargo build --workspace` clean (rustdoc syntax in code
  blocks does not break compilation).
- R8. The PR body is authored in `/tmp/`, scrubbed via Vale + LanguageTool + `unslop` (must score 0), and submitted via
  `gh pr create --body-file` per `RELEASES.md` § Prose scrubbing.

## Key Technical Decisions

- **KTD1. README structure: add sections incrementally, do not restructure.** The existing nine top-level sections stay.
  New content lands in the relevant existing subsections, plus one new top-level `## Troubleshooting`. A wholesale
  rewrite would risk losing established cross-references.

- **KTD2. The X Platform Enrollment Troubleshooting section mirrors upstream wording.** Users moving from `xurl` (Go) to
  `xr` (Rust) recognize the recipe. The five-step "Move to package → Pay-per-use → Production" recipe is the actionable
  form; the one-paragraph dedicated-section form is the index entry that grep finds. Both shapes appear upstream and we
  include both.

- **KTD3. Version bump and CHANGELOG belong on the release branch.** Per `RELEASES.md`, `Cargo.toml` version bumps and
  `CHANGELOG.md` regeneration via `scripts/generate-changelog.sh` happen on the `release/v1.3.0` branch when cutting the
  release from `dev` to `main`. They are intentionally absent from internal dev PRs.

- **KTD4. PR body uses neutral language.** No "PR N of M" framing, no AI attribution. The PR body presents the
  user-visible documentation additions without exposing the multi-PR planning structure that produced the feature work
  being documented.
