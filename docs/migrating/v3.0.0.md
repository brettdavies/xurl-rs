# Migrating to xurl 3.0.0

xurl 3.0.0 tracks X API OpenAPI spec 2.168. Upstream renamed the `Tweet` component schema to `Post` and moved the
tweet-era vocabulary with it, and xurl follows the spec everywhere it names things itself: the typed response types, the
`xr validate --schema` tokens, the committed response schemas, and the query parameters the shortcuts send. That rename
is the breaking surface this guide covers.

If you only use the `xr` CLI, skip to [CLI changes](#cli-changes). The shortcuts pass X's response body through
unchanged, so what changes for you is which field names X now sends and which `--schema` tokens `xr validate` accepts.

If you depend on `xurl` as a Rust library on crates.io, read every section.

## Rename table

| 2.x                                | 3.0                              | Where it appears                                       |
| ---------------------------------- | -------------------------------- | ------------------------------------------------------ |
| `Tweet`                            | `Post`                           | library type; `xr schema` type name; schema `$defs`    |
| `TweetPublicMetrics`               | `PostPublicMetrics`              | library type; schema `$defs`                           |
| `ReferencedTweet`                  | `ReferencedPost`                 | library type; schema `$defs`                           |
| `RetweetedResult`                  | `RepostedResult`                 | library type for `repost` / `unrepost`; schema `$defs` |
| `Includes.tweets`                  | `Includes.posts`                 | library field; `includes.posts` in response JSON       |
| `Tweet.referenced_tweets`          | `Post.referenced_posts`          | library field; `referenced_posts` in response JSON     |
| `TweetPublicMetrics.retweet_count` | `PostPublicMetrics.repost_count` | library field; `public_metrics.repost_count` in JSON   |
| `UserPublicMetrics.tweet_count`    | `UserPublicMetrics.post_count`   | library field; `public_metrics.post_count` in JSON     |
| `--schema tweet` / `tweets`        | `--schema post` / `posts`        | `xr validate`                                          |
| `tweet.fields`                     | `post.fields`                    | query parameter every post-reading shortcut sends      |

There is no alias window. The 2.x names are gone from the library, the validator, and the schemas.

## Library type renames

Before (2.x):

```rust
use xurl::api::{ApiResponse, Tweet, RetweetedResult, deserialize_response};

let resp: ApiResponse<Vec<Tweet>> = deserialize_response(value)?;
for post in &resp.data {
    if let Some(metrics) = &post.public_metrics {
        println!("{} reposts", metrics.retweet_count);
    }
    if let Some(refs) = &post.referenced_tweets {
        println!("references {} posts", refs.len());
    }
}
let quoted = resp.includes.and_then(|inc| inc.tweets);
let result: ApiResponse<RetweetedResult> = deserialize_response(repost_value)?;
```

After (3.0):

```rust
use xurl::api::{ApiResponse, Post, RepostedResult, deserialize_response};

let resp: ApiResponse<Vec<Post>> = deserialize_response(value)?;
for post in &resp.data {
    if let Some(metrics) = &post.public_metrics {
        println!("{} reposts", metrics.repost_count);
    }
    if let Some(refs) = &post.referenced_posts {
        println!("references {} posts", refs.len());
    }
}
let quoted = resp.includes.and_then(|inc| inc.posts);
let result: ApiResponse<RepostedResult> = deserialize_response(repost_value)?;
```

The struct field names are the wire names: there are no serde renames, so a 3.0 type deserializes the 2.168 response
shape directly. Two wire strings keep X's spelling inside the renamed types:

- `RepostedResult.retweeted` is still `retweeted`. The `/2/users/{id}/retweets` endpoint returns that key.
- `ReferencedPost.r#type` still carries `"retweeted"` as the repost reference kind, alongside `"replied_to"` and
  `"quoted"`.

`UserPublicMetrics.post_count` reads either `post_count` or `tweet_count`. The 2.168 spec names the field `post_count`;
the wire sends `tweet_count`, so the alias is what fills the typed field on a live response. The consumed key does not
also land in `extra`.

## Request-side changes

Every shortcut that reads posts (`read`, `search`, `timeline`, `mentions`, `likes`, `bookmarks`, `quote`, `reply`,
`post`) now sends `post.fields` instead of `tweet.fields`. Two values also moved out of the fields enum in 2.168 and are
requested through `expansions` instead:

- `in_reply_to_user_id` and `referenced_posts` on post reads.
- `sender_id` on `xr dms`, which left `dm_event.fields`.

If you build `RequestTarget::Template` queries yourself, make the same switch: send `post.fields`, and move
`in_reply_to_user_id` and referenced posts onto `expansions`. The 2.168 spec no longer lists them under `post.fields`.

## CLI changes

### Response JSON

Shortcut commands (`xr read`, `xr user`, and the rest) print the typed response, so field names follow the 3.0 types.
Post objects carry `public_metrics.repost_count` and `referenced_posts`; expanded posts arrive under `includes.posts`;
user objects carry `public_metrics.post_count`, filled from the `tweet_count` X sends. Fields the types do not name
(`like_count` and `media_count` on users, for example) pass through untouched. Raw `xr <URL>` calls print X's body
unchanged, so a user read there shows `tweet_count`. A script that selects `retweet_count`, `referenced_tweets`, or
`includes.tweets` from shortcut output reads nothing back and needs the new names.

### `xr validate --schema`

```text
$ echo '{"data":{"id":"1","text":"hi"}}' | xr validate --schema tweet --output json | jaq -c '{reason, exit_code}'
{"reason":"unknown-schema","exit_code":1}
$ echo '{"data":{"id":"1","text":"hi"}}' | xr validate --schema post --output json
{
  "schema": "post",
  "status": "ok",
  "valid": true
}
```

The `tweet` and `tweets` tokens are removed; use `post` and `posts`. The `unknown-schema` envelope lists every accepted
token under `known_schemas`. Auto-detect labels follow the same names. A new `credits` token validates the `xr usage
credits` response.

### `xr schema`

`xr schema --list` and `xr schema <command>` name `ApiResponse<Post>`, `ApiResponse<Vec<Post>>`, and
`ApiResponse<RepostedResult>`. The committed files under `schema/responses/` use the renamed `$defs` (`Post`,
`PostPublicMetrics`, `ReferencedPost`, `RepostedResult`). Tooling that pins `$defs/Tweet` needs `$defs/Post`.

### New: `xr usage credits`

`xr usage credits` reads `/2/usage/credits`, the credits-based usage endpoint 2.168 adds. Bare `xr usage` keeps reading
`/2/usage/tweets`. This is an addition, not a break.

## Unchanged

Wire strings the spec keeps under X's names are untouched:

- Endpoint paths: `/2/tweets/{id}`, `/2/users/{id}/retweets/{source_tweet_id}`, and the rest of the `/2/tweets` family.
- Request body and path keys: `tweet_id`, `source_tweet_id`.
- OAuth2 scopes: `tweet.read`, `tweet.write`.
- The `tweet_image` media category on `xr media upload`.
- Exit codes, error envelopes, the `--output` formats, and the auth-method validator from 2.0.0.
