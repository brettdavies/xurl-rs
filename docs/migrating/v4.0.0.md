# Migrating to xurl-rs 4.0.0

xurl-rs 4.0.0 is the release where the X API client behind `xr` becomes its own crate. The library is `xdk-rs` on
crates.io (`use xdk::`), starting at 0.1.0; `xurl-rs` is the command-line tool only. That split is the breaking surface
this guide covers.

If you only use the `xr` CLI, skip to [CLI changes](#cli-changes): nothing about installing or running `xr` changed.

If you depend on `xurl` as a Rust library on crates.io, read every section. The 3.x `xurl` library target is gone from
`xurl-rs`; the crate still builds a hidden `xurl` library for its own tests, and it is not an API.

## Rename table

| 3.x                                                     | 4.0 / xdk-rs 0.1                                                       | Where it appears                         |
| ------------------------------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------- |
| `xurl-rs = "3"` (library)                               | `xdk-rs = "0.1"`                                                       | `Cargo.toml`                             |
| `use xurl::`                                            | `use xdk::`                                                            | every import                             |
| `xurl::api::ApiClient::new(&cfg, auth)`                 | `xdk::api::Client::builder()...build()?` or `Client::new(&cfg, auth)?` | client construction                      |
| `client.search_posts("q", 10, &opts)?` (blocking)       | `client.search_posts("q", 10).send().await?`                           | every shortcut                           |
| `CallOptions`                                           | methods on `Call<T>`: `auth`, `username`, `trace`, `timeout`, `header` | per-call options                         |
| `xurl::XurlError`                                       | `xdk::Error` (`#[non_exhaustive]`), `xdk::Result`                      | error handling                           |
| `XurlError::Auth("Auth Error: ...")` Display            | lowercase fragment, no prefix, no trailing period                      | error messages                           |
| `xurl::cli::hints::NextAction`                          | `xdk::error::NextAction` via `Error::next_action()`                    | recovery hints                           |
| `client.stream_request(&opts)` (iterator)               | `client.stream_request(&opts).await?` (`Stream`)                       | streaming                                |
| `xurl::output`, `xurl::envelope`, `xurl::skill_install` | gone from the library; they are `xr`'s own                             | rendering, exit envelopes, skill bundles |
| `Auth::oauth2_flow(...)` with output config             | `Client::oauth2_flow(username, cancel, opener)`                        | browser sign-in                          |

There is no alias window. The `xurl` library names are gone; `xdk` is the only library.

## The client is async, and every shortcut is a builder

The 3.x client was blocking and every shortcut took a `&CallOptions`. The 4.0 library is async on tokio, holds one
HTTP client, and every shortcut returns a `Call<T>` finished by `.send().await`.

Before (3.x):

```rust
use xurl::api::{ApiClient, CallOptions};
use xurl::auth::Auth;
use xurl::config::Config;

let cfg = Config::new();
let mut client = ApiClient::new(&cfg, Auth::new(&cfg));
let opts = CallOptions::default();
let posts = client.search_posts("rust", 10, &opts)?;
for post in &posts.data {
    println!("{}: {}", post.id, post.text);
}
```

After (4.0):

```rust
use xdk::api::Client;

#[tokio::main]
async fn main() -> xdk::Result<()> {
    let client = Client::builder()
        .bearer(std::env::var("XURL_BEARER_TOKEN").expect("XURL_BEARER_TOKEN"))
        .build()?;
    let posts = client.search_posts("rust", 10).send().await?;
    for post in &posts.data {
        println!("{}: {}", post.id, post.text);
    }
    Ok(())
}
```

`Client::new(&Config, Auth)` and `Client::from_env()` still build a client over the `~/.xurl` token store the CLI
writes; `Client::builder()` is the path for a credential held in code (bearer, `OAuth2Credential`, or
`OAuth1Credential`). A `Call<T>` is sent once; the per-call options that were fields on `CallOptions` are methods on the
call (`auth(WireScheme)`, `username(..)`, `trace(bool)`, `timeout(Duration)`, `header(name, value)`).

## Errors

`XurlError` is `xdk::Error`, re-exported at the crate root beside `xdk::Result`. The enum is `#[non_exhaustive]`, so a
match needs a wildcard arm. Display strings are lowercase fragments with no `Auth Error:` style prefix and no trailing
period; the `xr` renderer adds the prefixes, so the CLI prints what it printed. The exit code and the machine-readable
recovery hint are methods on the error.

Before (3.x):

```rust
use xurl::error::{XurlError, exit_code_for_error};

match client.get_me(&opts) {
    Ok(me) => println!("{}", me.data.username),
    Err(XurlError::Auth(msg)) => {
        eprintln!("{msg}");
        std::process::exit(exit_code_for_error(&XurlError::Auth(msg)));
    }
    Err(err) => return Err(err),
}
```

After (4.0):

```rust
use xdk::Error;

match client.get_me().send().await {
    Ok(me) => println!("{}", me.data.username),
    Err(err @ Error::Auth(_)) => {
        eprintln!("{}: {err}", err.kind());
        if let Some(action) = err.next_action() {
            eprintln!("next: {action:?}");
        }
        std::process::exit(err.exit_code());
    }
    Err(err) => return Err(err),
}
```

`EnvelopeAlreadyEmitted` left the enum; it was a CLI sentinel. `Error::docs_url()` names the page that explains an
error when one exists.

## Streaming

`stream_request` returns a `StreamLines` that implements `futures_core::Stream<Item = Result<String>>` and offers
`next_line().await`; the caller drives the loop and decides when to stop.

Before (3.x):

```rust
for line in client.stream_request(&opts)? {
    println!("{}", line?);
}
```

After (4.0):

```rust
let mut lines = client.stream_request(&opts).await?;
while let Some(line) = lines.next_line().await? {
    println!("{line}");
}
```

## Sign-in

`Auth::oauth2_flow` took an output config, a writer, and a browser-opening function pointer, and the library opened the
browser and printed progress itself. The library no longer performs terminal I/O or launches a browser: the flow takes a
cancellation token and an opener closure, and returns the username it signed in.

Before (3.x):

```rust
let username = auth.oauth2_flow(&out, &mut stderr, open::that, None)?;
```

After (4.0):

```rust
use tokio_util::sync::CancellationToken;

let username = client
    .oauth2_flow("", CancellationToken::new(), |url| open::that(url))
    .await?;
```

Diagnostics that were `--verbose` prints are `tracing` events on the `xdk::wire`, `xdk::media`, `xdk::auth`,
`xdk::store`, and `xdk::config` targets; install a subscriber to see them.

## Presentation moved into the binary

`xurl::output` (`OutputConfig`, `OutputFormat`, `ColorChoice`, `format_response`), `xurl::envelope`, and
`xurl::skill_install` are not part of `xdk`; they render for a terminal and belong to `xr`. A program that used
`format_response` to colour JSON prints the `serde_json::Value` it holds; the typed responses implement `Serialize`.

## CLI changes

Nothing. Installing `xr` through Homebrew, `cargo install xurl-rs`, `cargo binstall xurl-rs`, or a release archive is
unchanged, the archive names are unchanged, and every command prints what 3.2.0 printed; a golden-output suite of 103
fixtures captured from 3.2.0 is re-asserted byte for byte on every test run. Two additions:

- `xr version --verbose` prints `xr 4.0.0 (xdk-rs 0.1.0)`, and `xr version --output json` prints
  `{"name": "xr", "version": "4.0.0", "xdk_rs": "0.1.0"}`, so a bug report names both versions. Plain `xr --version`
  and `xr version` still print `xr 4.0.0` and nothing else.
- The `xurl-rs` package no longer declares a public library; a `Cargo.toml` that depended on `xurl-rs` for the library
  moves that line to `xdk-rs`.

## Unchanged

- The `~/.xurl` token store, its format, and the `XURL_*` environment variables.
- Endpoint paths, request bodies, the typed response types and their field names from 3.0.0, and the OAuth2 scopes.
- Exit codes, error envelopes, the `--output` formats, and the auth-method validator.
