# Migrating to xr 4.9.0: a minor under the small-break exception

`xr` 4.9.0 reads an answer from X's OAuth2 token endpoint as a refusal only when its JSON body names one of the six
error codes of RFC 6749 section 5.2. In 4.8 a 400 or a 401 counted as a refusal by its status alone, and any other
status but a 5xx or a 429 counted when its JSON body held any string `error`. So a proxy's or a gateway's error told the
user that their login or client was refused and to sign in again. In 4.9 such an answer reports its status, with a step
that names `TOKEN_URL` and the proxy in front of it. The change ships in a minor release under the small-break exception
(`RELEASES.md` § "The bump"): X's own handler always names its error code, so the answers that move are the ones a
proxy, a firewall, or a wrong `TOKEN_URL` gives, and every answer X's handler gives keeps its `reason`, `exit_code`, and
`next_step`.

## What counts as a refusal

An answer is a refusal when its status is no 5xx and no 429 and its JSON body's `error` is `invalid_request`,
`invalid_client`, `invalid_grant`, `unauthorized_client`, `unsupported_grant_type`, or `invalid_scope`. A refusal is
`auth-required` at exit 77, as in 4.8: `sign-in` for a refused code or refresh token, and `fix-input` with no invocation
for a refused client (a 401, `invalid_client`, or `unauthorized_client`). X's page on the token endpoint's errors names
five of the six on a 400, the sixth being RFC 6749's own:
[Migrate from OAuth 1.0a to OAuth 2.0](https://docs.x.com/fundamentals/authentication/oauth-2-0/oauth-1-0a-token-exchange).
It names `rate_limited` and `temporarily_unavailable` too, on a 429 and a 503, which are never refusals.

## Answers that stopped being refusals

The sign-in's code exchange (`xr auth oauth2 --step 2`) and the refresh a command runs when its login has expired read
the answer the same way. Each row holds for both, and under step 2 the saved sign-in stays for the next try.

| Answer from the token endpoint                                             | 4.8: `reason`, `exit_code`, `next_step.action`                            | 4.9: `reason`, `exit_code`, `next_step.action`                  |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 400 with no body, a body that is not JSON, or an `error` outside the six   | `auth-required`, 77, `sign-in`                                            | `invalid-request`, 1, `fix-input`, `docs` on the README section |
| 401 with no body, a body that is not JSON, or an `error` outside the six   | `auth-required`, 77, `fix-input` with no invocation                       | `api-error`, 1, `fix-input`, `docs` on the README section       |
| 403 with a string `error` outside the six                                  | `auth-required`, 77, `sign-in`                                            | `forbidden`, 1, `fix-input`, `docs` on the README section       |
| 404 with a string `error` outside the six                                  | `auth-required`, 77, `sign-in`                                            | `not-found`, 4, `fix-input`, `docs` on X's response-codes page  |
| 408 with a string `error` outside the six                                  | `auth-required`, 77, `sign-in`                                            | `api-error`, 1, `retry`, `docs` on X's response-codes page      |
| Any other status but a 5xx or a 429, with a string `error` outside the six | `auth-required`, 77, `sign-in`                                            | `api-error`, 1, `fix-input`, `docs` on the README section       |
| Any other status but a 403, a 404, a 408, a 5xx, or a 429, with no `error` | `api-error`, 1, `report-issue`, `docs` on the issue tracker               | `api-error`, 1, `fix-input`, `docs` on the README section       |
| A 3xx redirect, which 4.9 no longer follows                                | the redirect was followed, and the answer that came back was read instead | `api-error`, 1, `fix-input`, `docs` on the README section       |
| A 403 with no string `error`, a 404 or a 408 with none, a 5xx, a 429       | unchanged                                                                 | unchanged                                                       |
| Any status with one of the six codes in its JSON `error`                   | unchanged                                                                 | unchanged                                                       |

"The README section" is [The OAuth2 token endpoint](https://github.com/brettdavies/xurl-rs#the-oauth2-token-endpoint),
which covers `TOKEN_URL` and proxies. A string `error` is a JSON body whose `error` is a string. A 400 or a 401 with a
body that holds `{"error": "invalid_grant"}` is a refusal in both versions, and so is that body on a 403, a 404, or
a 408.

The `message` of an answer that is no refusal is the body the endpoint sent, or
`the token endpoint answered <status> with an empty body` when it sent none, where 4.8 wrote
`Auth Error: RefreshTokenError: the token endpoint refused the refresh token: HTTP <status>`. Each such answer also
carries a `warnings` entry that names the token endpoint, the grant, and the HTTP status. Text output closes with
`The token endpoint answered <status> and sent no OAuth error code`, then the two things to check, `TOKEN_URL` and a
proxy or firewall in front of the endpoint, and the README link.

`xr --output json whoami` with an expired login, against a token endpoint that answers 400 with no body:

```json
{
  "exit_code": 77,
  "message": "Auth Error: RefreshTokenError: the token endpoint refused the refresh token: HTTP 400 Bad Request",
  "next_step": {
    "action": "sign-in",
    "command": "xr auth oauth2 alice --no-browser --step 1"
  },
  "reason": "auth-required",
  "status": "error"
}
```

4.9:

```json
{
  "exit_code": 1,
  "message": "the token endpoint answered 400 with an empty body",
  "next_step": {
    "action": "fix-input",
    "docs": "https://github.com/brettdavies/xurl-rs#the-oauth2-token-endpoint"
  },
  "reason": "invalid-request",
  "status": "error",
  "warnings": [
    {
      "message": "the token endpoint answered the OAuth2 login's refresh with HTTP 400 Bad Request",
      "target": "xdk::auth"
    }
  ]
}
```

## Scripts

A script that took exit 77 from a refresh or a sign-in to mean "sign in again" now sees it only for an answer that names
an OAuth error code. A proxy's or a gateway's answer ends at exit 1, or exit 4 for a 404, with `fix-input`, so the next
move is to check `TOKEN_URL` and the proxy, not to open a browser.

| 4.8                                                               | 4.9                                                                                          |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `jaq 'select(.reason == "auth-required")'` matches a 400 or a 401 | the same filter matches only a refusal, and the answers above no longer match                |
| `jaq 'select(.next_step.action == "report-issue")'` matches a 418 | the filter no longer matches a token endpoint answer: it is `fix-input` with the README link |

## Library

`xdk-rs` 0.9.0 reports the same split in `xdk::Error`. A 400 or a 401 with no RFC 6749 error code, a redirect, and any
status with no reading of its own, which is every one but a 403, a 404, a 408, a 429, and a 5xx, is the new
`Error::TokenEndpointUnexpected { status, body }`, where 0.8 returned `Error::Auth` for a 400, a 401, or any status
whose body held a string `error`, and `Error::Api` for the rest. `Error::kind()` is `invalid-request` for a 400 and
`api-error` for the others, `exit_code()` is 1, `next_action()` is `FixInput`, and `docs_url()` is the README section. A
403 stays `Error::TokenEndpointForbidden`, and a 404, a 408, a 429, and a 5xx stay `Error::Api`.

```rust
// 0.8
match client.get_me().send().await {
    Err(Error::Auth { .. }) => sign_in_again(),
    Err(Error::Api { status, .. }) => report(status),
    other => other.map(drop).unwrap_or(()),
}

// 0.9
match client.get_me().send().await {
    Err(Error::Auth { .. }) => sign_in_again(),
    Err(Error::TokenEndpointUnexpected { status, .. }) => check_token_url_and_proxy(status),
    Err(Error::Api { status, .. }) => report(status),
    other => other.map(drop).unwrap_or(()),
}
```
